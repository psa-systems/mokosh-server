# PMS-1286: paths whose noseyparker findings are provably false positives
# (test fixtures, dev defaults, docs examples, env-var NAME literals, CI
# templates, AWS official reference credentials). One sentence per entry
# naming WHY the exclusion is safe. A real secret in any of these paths is
# the same incident class a scan on a clean path would catch; add the file
# individually rather than widening a parent glob so a future contributor
# cannot land a real secret under cover of this file.

# Integration test fixtures: every password here is a throwaway seeded by
# `tests/common/mod.rs` against the per-test disposable Postgres and
# redeemed inside the same test run.
tests/

# Documentation examples. `quickstart.md`'s `at-least-12-characters` and
# `codebase-state.md`'s `devpassword12` are the strings the operator is
# told to type, not credentials in use.
docs/

# Dev-stack entrypoint. `.env` is generated per clone via `openssl rand`
# in the `ensure-env` recipe; the strings here are Nushell variable
# templates (`($pg_password)`, `($infisical_pg_password)`, etc.) that
# resolve to the generated values at run time, never shipped as literals.
justfile

# Env-var NAME string literals. The text `ADMIN_PASSWORD`, `SMTP_PASSWORD`
# etc. names the key an operator sets; the value lives in `.env`, Infisical
# or the application-secret provider and never in these files.
src/config/registry.rs
src/app_secrets/mod.rs

# Dev-only default. `AppConfig::from_env` falls back to
# `postgres://postgres:postgres@localhost:5432/mokosh` so a fresh clone
# can boot; production refuses an unset DATABASE_URL and the probe at
# `provision.rs` fails before this fallback is reached.
src/main.rs

# Lazy-pool fixtures in two routing tests. The URL
# `postgres://unused:unused@127.0.0.1:1/unused` builds a `PgPool::connect_lazy`
# that NEVER connects, used to assert the router produces 404 for an
# unmounted path without touching the database.
src/modules/auth/routes.rs
src/modules/forms/routes.rs

# Dotenv-upsert round-trip fixture. `postgres://user:p=ssw=rd@host:5432/db`
# exercises an `=` char in a stored password, not a credential.
src/infisical/dev.rs

# AWS SigV4 reference test vectors. `AKIAIOSFODNN7EXAMPLE` and the paired
# secret `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY` are the documented
# example credentials from docs.aws.amazon.com's SigV4 signing guide.
src/storage/s3.rs

# Documentation URL in a header comment showing an operator the command to run.
scripts/audit-portal-no-credential.nu

# CI service postgres uses the default `postgres` superuser login against a
# container-scoped database that lives only for the duration of the job.
.forgejo/workflows/
